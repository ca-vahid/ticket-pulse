# Tickets UX Uplift — Phased Plan & Task Board

> Status: **✅ COMPLETE — all three phases implemented & browser-verified on the prod-data dev stack** (2026-07-01). Uncommitted, up in dev for review.
> Source: designer mockup at `qa/ticket-pulse-tickets/` (two audit passes: full feature inventory + micro-behavior sweep) vs. the shipped native-ticketing surfaces, plus an our-side gap audit.
> Scope: **ticket queue, ticket detail page, and the create/reply flow only.** Everything else in the mockup (dashboard redesign, onboarding/offboarding modules, sub-nav IA, leaderboards) is out of scope.
> Principle: adopt **features and interaction patterns**, not a 1:1 visual copy — our glass/blue language stays.

## Decisions locked (from review)

| Topic | Decision |
|---|---|
| Time tracking | **Out.** |
| Per-ticket task checklists | **Out** for now. |
| Per-ticket watchers | **Out.** Future watchers are **per category (top/sub) or per group** — planned in T3. |
| Tags | **Out of scope.** |
| One-click "Pick up" | In, **with a confirmation step**. |
| Related tickets | Accuracy first: only claims that are *provably true* ("Other tickets from this requester"); fuzzy similarity only as a clearly-labeled suggestion. |
| Groups | Plan for **mailbox→group routing**: multiple monitored mailboxes in one workspace (e.g. Accounting: AP@ and AR@) route tickets into different **groups**, with categories/subcategories layering on top. Feature-ready even though not yet used in practice. |

## Excluded by decision
Time tracking · per-ticket tasks · per-ticket watchers · tags · leaderboards (team-safe rule) · assets/associations (FS CMDB) · onboarding/offboarding request modules · KB "related articles" · dashboard redesign · purple sub-nav IA.
